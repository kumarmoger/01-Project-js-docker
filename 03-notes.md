# Docker Volumes

## What is a Docker Volume?

A **Docker Volume** is a storage mechanism used to persist data generated by containers.

By default, when a container is deleted, all data inside the container is lost. Volumes allow data to remain available even after the container is stopped, removed, or recreated.

### Without a Volume

Run a container:

```bash
docker run -it ubuntu
```

Inside the container:

```bash
echo "Hello Docker" > file.txt
```

If the container is removed:

```bash
docker rm <container-id>
```

The file is lost forever because it was stored inside the container.

### With a Volume

Create a volume:

```bash
docker volume create mydata
```

Run a container with the volume mounted:

```bash
docker run -it -v mydata:/data ubuntu
```

Inside the container:

```bash
echo "Hello Docker" > /data/file.txt
```

Even if the container is removed, the data remains in the volume.

---

## Why Do We Need Volumes?

Volumes are mainly used for:

### 1. Data Persistence

Database data should not disappear when containers restart.

Examples:

* MongoDB
* MySQL
* PostgreSQL
* Redis

```bash
docker run -d \
-v mongo-data:/data/db \
mongo
```

MongoDB stores its database files in the volume.

### 2. Data Sharing Between Containers

Multiple containers can access the same volume.

```bash
docker run -d --name container1 -v shared-data:/app/data nginx

docker run -d --name container2 -v shared-data:/app/data nginx
```

Both containers can read and write the same files.

### 3. Backup and Restore

Volumes can be backed up and restored independently of containers.

# Types of Docker Storage

Docker provides three major storage options:

1. Named Volumes
2. Anonymous Volumes
3. Bind Mounts

---

## 1. Named Volumes

Docker creates and manages the volume.

### Create a Volume

```bash
docker volume create myvolume
```

### List Volumes

```bash
docker volume ls
```

Example output:

```text
DRIVER    VOLUME NAME
local     myvolume
```

### Inspect a Volume

```bash
docker volume inspect myvolume
```

Example output:

```json
[
  {
    "Name": "myvolume",
    "Driver": "local",
    "Mountpoint": "/var/lib/docker/volumes/myvolume/_data"
  }
]
```

Docker stores volume data in:

```text
/var/lib/docker/volumes/
```

*(Linux only)*

### Mount a Named Volume

Using `-v`:

```bash
docker run -d \
--name web \
-v myvolume:/usr/share/nginx/html \
nginx
```

#### Explanation

| Part                  | Description    |
| --------------------- | -------------- |
| myvolume              | Volume name    |
| :                     | Separator      |
| /usr/share/nginx/html | Container path |

Using `--mount`:

```bash
docker run -d \
--mount type=volume,src=myvolume,dst=/usr/share/nginx/html \
nginx
```

---

## 2. Anonymous Volumes

Anonymous volumes are automatically created by Docker.

Example:

```bash
docker run -v /data nginx
```

Docker creates a volume with a random name:

```text
6c3d8c0f1b1e8...
```

Check existing volumes:

```bash
docker volume ls
```

Example output:

```text
local 6c3d8c0f1b1e8...
```

### Drawback

You do not know the volume name beforehand because Docker generates it automatically.

### Use Cases

* Temporary storage
* Container images requiring a writable path
* Short-lived application data

---

## 3. Bind Mounts

Bind mounts map a host directory directly into the container.

### Example

Host directory:

```text
/home/dev/project
```

Container directory:

```text
/app
```

Run:

```bash
docker run \
-v /home/dev/project:/app \
node
```

Result:

```text
Host Files  <---->  Container Files
```

Any changes made on the host are immediately visible inside the container and vice versa.

Using `--mount`:

```bash
docker run \
--mount type=bind,src=/home/dev/project,dst=/app \
node
```

---

## Summary

* **Named Volumes** are best for persistent application and database data.
* **Anonymous Volumes** are Docker-managed volumes with auto-generated names.
* **Bind Mounts** directly connect host directories to containers and are commonly used during development.
* Volumes help preserve data even when containers are stopped, removed, or recreated.
